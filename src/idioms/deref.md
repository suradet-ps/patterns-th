# คอลเลกชันคือสมาร์ตพอยน์เตอร์

## คำอธิบาย

ใช้ trait [`Deref`](https://doc.rust-lang.org/std/ops/trait.Deref.html) เพื่อปฏิบัติต่อคอลเลกชันเสมือนสมาร์ตพอยน์เตอร์ โดยนำเสนอทั้งมุมมองแบบเป็นเจ้าของและมุมมองแบบยืมของข้อมูล

## ตัวอย่าง

```rust,ignore
use std::ops::Deref;

struct Vec<T> {
    data: RawVec<T>,
    //..
}

impl<T> Deref for Vec<T> {
    type Target = [T];

    fn deref(&self) -> &[T] {
        //..
    }
}
```

`Vec<T>` เป็นคอลเลกชันของ `T` แบบเป็นเจ้าของ ขณะที่สไลซ์ (`&[T]`) เป็นคอลเลกชันของ `T` แบบยืม การอิมพลีเมนต์ `Deref` ให้กับ `Vec` ทำให้เกิดการดึงค่าอ้างอิงโดยนัยจาก `&Vec<T>` ไปเป็น `&[T]` และรวมความสัมพันธ์นี้ไว้ในกระบวนการค้นหาการดึงค่าอ้างอิงอัตโนมัติ (auto-dereferencing) เมท็อดส่วนใหญ่ที่คุณอาจคาดว่าจะมีการอิมพลีเมนต์ให้กับ `Vec` กลับถูกอิมพลีเมนต์ให้กับสไลซ์แทน

นอกจากนี้ `String` และ `&str` ก็มีความสัมพันธ์ในลักษณะเดียวกัน

## แรงจูงใจ

ความเป็นเจ้าของและการยืมเป็นประเด็นสำคัญของภาษา Rust โครงสร้างข้อมูลต้องคำนึงถึงความหมายเชิงนี้อย่างเหมาะสมเพื่อให้ผู้ใช้ได้รับประสบการณ์ที่ดี เมื่ออิมพลีเมนต์โครงสร้างข้อมูลที่เป็นเจ้าของข้อมูล การนำเสนอุมมองแบบยืมของข้อมูลนั้นช่วยให้ API มีความยืดหยุ่นมากขึ้น

## ข้อดี

เมท็อดส่วนใหญ่สามารถอิมพลีเมนต์ไว้ที่มุมมองแบบยืมเท่านั้น แล้วจะใช้ได้โดยนัยกับมุมมองแบบเป็นเจ้าของด้วย

มอบทางเลือกให้ผู้เรียกใช้ระหว่างการยืมหรือการรับความเป็นเจ้าของข้อมูล

## ข้อเสีย

เมท็อดและ trait ที่เข้าถึงได้ผ่านการดึงค่าอ้างอิงเท่านั้นจะไม่ถูกนำมาพิจารณาเมื่อตรวจสอบขอบเขต (bounds checking) ดังนั้นการเขียนโปรแกรมเจเนอริกกับโครงสร้างข้อมูลที่ใช้แพตเทิร์นนี้อาจซับซ้อนได้ (ดู trait `Borrow`, `AsRef` เป็นต้น)

## การอภิปราย

สมาร์ตพอยน์เตอร์และคอลเลกชันมีความคล้ายคลึงกัน: สมาร์ตพอยน์เตอร์ชี้ไปยังออบเจกต์เดียว ขณะที่คอลเลกชันชี้ไปยังออบเจกต์หลายตัว จากมุมมองของระบบชนิด ทั้งสองแทบไม่มีความแตกต่างกัน คอลเลกชันเป็นเจ้าของข้อมูลของมันหากวิธีเดียวที่จะเข้าถึงข้อมูลแต่ละตัวคือผ่านคอลเลกชัน และคอลเลกชันมีหน้าที่ลบข้อมูลนั้น (แม้ในกรณีของความเป็นเจ้าของร่วม มุมมองแบบยืมบางรูปแบบก็อาจเหมาะสม) หากคอลเลกชันเป็นเจ้าของข้อมูล มักมีประโยชน์ที่จะนำเสนอุมมองของข้อมูลในแบบที่ถูกยืม เพื่อให้อ้างอิงซ้ำได้หลายครั้ง

สมาร์ตพอยน์เตอร์ส่วนใหญ่ (เช่น `Foo<T>`) อิมพลีเมนต์ `Deref<Target=T>` อย่างไรก็ตาม คอลเลกชันมักดึงค่าอ้างอิงไปเป็นชนิดที่กำหนดเอง `[T]` และ `str` มีการรองรับระดับภาษา แต่ในกรณีทั่วไปไม่จำเป็นต้องทำเช่นนั้น `Foo<T>` สามารถอิมพลีเมนต์ `Deref<Target=Bar<T>>` โดยที่ `Bar` เป็นชนิดที่มีขนาดกำหนดได้ที่รันไทม์ (dynamically sized type) และ `&Bar<T>` เป็นมุมมองแบบยืมของข้อมูลใน `Foo<T>`

โดยทั่วไป คอลเลกชันที่มีลำดับจะอิมพลีเมนต์ `Index` สำหรับ `Range` เพื่อรองรับไวยากรณ์การสไลซ์ โดยเป้าหมายจะเป็นมุมมองแบบยืม
