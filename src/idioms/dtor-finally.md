# การทำขั้นสุดท้ายในเดสทรัคเตอร์

## คำอธิบาย

Rust ไม่มีสิ่งที่เทียบเท่ากับบล็อก `finally` - โค้ดที่จะถูกเรียกใช้ไม่ว่าฟังก์ชันจะสิ้นสุดลงด้วยวิธีใดก็ตาม แต่เราสามารถใช้เดสทรัคเตอร์ (destructor) ของออบเจกต์เพื่อรันโค้ดที่ต้องรันก่อนออกจากฟังก์ชันได้

## ตัวอย่าง

```rust,ignore
fn baz() -> Result<(), ()> {
    // some code
}

fn bar() -> Result<(), ()> {
    // These don't need to be defined inside the function.
    struct Foo;

    // Implement a destructor for Foo.
    impl Drop for Foo {
        fn drop(&mut self) {
            println!("exit");
        }
    }

    // The destructor of _exit will run however the function `bar` is exited.
    let _exit = Foo;
    // Implicit return with `?` operator.
    baz()?;
    // Normal return.
    Ok(())
}
```

## แรงจูงใจ

หากฟังก์ชันมีจุด return หลายจุด การรันโค้ดตอนออกจากฟังก์ชันจะกลายเป็นเรื่องยากและต้องเขียนซ้ำหลายที่ (จึงเสี่ยงต่อบั๊ก) โดยเฉพาะในกรณีที่การ return เกิดขึ้นโดยนัยผ่านมาโคร กรณีพบได้บ่อยคือโอเปอเรเตอร์ `?` ซึ่งจะ return หากผลลัพธ์เป็น `Err` แต่ทำงานต่อหากเป็น `Ok` เราใช้ `?` เป็นกลไกจัดการข้อยกเว้น แต่ต่างจาก Java (ซึ่งมี `finally`) ตรงที่เราไม่มีวิธีกำหนดให้โค้ดรันทั้งในกรณีปกติและกรณีผิดปกติ การ panic ก็ทำให้ฟังก์ชันออกก่อนกำหนดได้เช่นกัน

## ข้อดี

โค้ดในเดสทรัคเตอร์จะ (เกือบ) ถูกเรียกใช้เสมอ - รับมือกับการ panic, การ return ก่อนกำหนด ฯลฯ

## ข้อเสีย

ไม่มีการรับประกันว่าเดสทรัคเตอร์จะถูกเรียกใช้ ตัวอย่างเช่น หากมีลูปไม่สิ้นสุดในฟังก์ชัน หรือหากการรันฟังก์ชันเกิดพังก่อนออกจากฟังก์ชัน เดสทรัคเตอร์ยังไม่ถูกเรียกใช้ในกรณีที่เกิด panic ในเธรดที่กำลัง panic อยู่แล้ว ดังนั้นจึงไม่อาจพึ่งพาเดสทรัคเตอร์เป็นตัวทำขั้นสุดท้ายได้ในกรณีที่การทำขั้นสุดท้ายจำเป็นอย่างยิ่ง

แพตเทิร์นนี้เพิ่มโค้ดโดยนัยที่สังเกตได้ยาก การอ่านฟังก์ชันไม่ให้สัญญาณชัดเจนว่าจะมีเดสทรัคเตอร์รันตอนออกจากฟังก์ชัน ซึ่งทำให้การดีบักเป็นเรื่องยุ่งยากได้

การต้องมีออบเจกต์และการอิมพลีเมนต์ `Drop` เพียงเพื่อทำขั้นสุดท้ายนั้นมีโค้ดซ้ำซาก (boilerplate) มาก

## การอภิปราย

มีความละเอียดอ่อนบางประการเกี่ยวกับวิธีเก็บออบเจกต์ที่ใช้เป็นตัวทำขั้นสุดท้ายให้ถูกต้อง มันต้องคงอยู่จนถึงสิ้นสุดฟังก์ชันแล้วจึงถูกทำลาย ออบเจกต์นั้นต้องเป็นค่าหรือพอยน์เตอร์ที่เป็นเจ้าของแบบเอกลักษณ์เสมอ (เช่น `Box<Foo>`) หากใช้พอยน์เตอร์แบบใช้ร่วม (เช่น `Rc`) ตัวทำขั้นสุดท้ายอาจคงอยู่เลยอายุของฟังก์ชันไป ด้วยเหตุผลคล้ายกัน ตัวทำขั้นสุดท้ายจึงไม่ควรถูกย้ายหรือส่งคืน

ตัวทำขั้นสุดท้ายต้องถูกผูกเข้ากับตัวแปร มิฉะนั้นมันจะถูกทำลายทันที แทนที่จะรอจนออกจากขอบเขต ชื่อตัวแปรต้องขึ้นต้นด้วย `_` หากตัวแปรถูกใช้เป็นตัวทำขั้นสุดท้ายเท่านั้น มิฉะนั้นคอมไพเลอร์จะเตือนว่าตัวทำขั้นสุดท้ายไม่เคยถูกใช้ อย่างไรก็ตาม อย่าตั้งชื่อตัวแปรว่า `_` เฉยๆ - ในกรณีนั้นมันจะถูกทำลายทันที

ใน Rust เดสทรัคเตอร์จะถูกเรียกใช้เมื่อออบเจกต์ออกจากขอบเขต ซึ่งเกิดขึ้นไม่ว่าเราจะไปถึงจุดสิ้นสุดของบล็อก มีการ return ก่อนกำหนด หรือโปรแกรมเกิด panic เมื่อ panic Rust จะคลายสแตก (unwind) โดยเรียกเดสทรัคเตอร์ของแต่ละออบเจกต์ในแต่ละสแตกเฟรม ดังนั้นเดสทรัคเตอร์จึงถูกเรียกแม้ panic จะเกิดในฟังก์ชันที่ถูกเรียกอยู่

หากเดสทรัคเตอร์เกิด panic ระหว่างการคลายสแตก ก็ไม่มีทางเลือกที่ดีให้ทำ Rust จึงยกเลิกเธรดทันทีโดยไม่เรียกเดสทรัคเตอร์ตัวอื่นต่อ ซึ่งหมายความว่าไม่มีการรับประกันเด็ดขาดว่าเดสทรัคเตอร์จะได้รัน และยังหมายความว่าคุณต้องระมัดระวังเป็นพิเศษไม่ให้เดสทรัคเตอร์ panic เพราะอาจทิ้งทรัพยากรไว้ในสถานะที่ไม่คาดคิด
