# `mem::{take(_), replace(_)}` เพื่อรักษาค่าที่เป็นเจ้าของไว้ใน enum ที่เปลี่ยนแปลง

## คำอธิบาย

สมมติว่าเรามี `&mut MyEnum` ซึ่งมีอย่างน้อยสอง variant คือ
`A { name: String, x: u8 }` และ `B { name: String }` ตอนนี้เราต้องการเปลี่ยน
`MyEnum::A` ให้เป็น `B` หาก `x` มีค่าเป็นศูนย์ โดยที่ `MyEnum::B` ยังคงเดิม

เราทำเช่นนี้ได้โดยไม่ต้องโคลน `name`

## ตัวอย่าง

```rust
use std::mem;

enum MyEnum {
    A { name: String, x: u8 },
    B { name: String },
}

fn a_to_b(e: &mut MyEnum) {
    if let MyEnum::A { name, x: 0 } = e {
        // This takes out our `name` and puts in an empty String instead
        // (note that empty strings don't allocate).
        // Then, construct the new enum variant (which will
        // be assigned to `*e`).
        *e = MyEnum::B {
            name: mem::take(name),
        }
    }
}
```

วิธีนี้ยังใช้ได้กับกรณีที่มีหลาย variant:

```rust
use std::mem;

enum MultiVariateEnum {
    A { name: String },
    B { name: String },
    C,
    D,
}

fn swizzle(e: &mut MultiVariateEnum) {
    use MultiVariateEnum::*;
    *e = match e {
        // Ownership rules do not allow taking `name` by value, but we cannot
        // take the value out of a mutable reference, unless we replace it:
        A { name } => B {
            name: mem::take(name),
        },
        B { name } => A {
            name: mem::take(name),
        },
        C => D,
        D => C,
    }
}
```

## แรงจูงใจ

เมื่อทำงานกับ enum เราอาจต้องการเปลี่ยนค่า enum ในที่เดิม อาจเปลี่ยนไปเป็น variant อื่น ซึ่งปกติทำเป็นสองระยะเพื่อให้ borrow checker พอใจ ในระยะแรก เราสังเกตค่าที่มีอยู่และดูส่วนประกอบของมันเพื่อตัดสินใจว่าจะทำอะไรต่อ ในระยะที่สองเราอาจเปลี่ยนค่าแบบมีเงื่อนไข (ดังในตัวอย่างข้างต้น)

borrow checker จะไม่ยอมให้เราดึง `name` ออกมาจาก enum (เพราะ*บางสิ่ง*ต้องอยู่ตรงนั้น) แน่นอนว่าเราสามารถ `.clone()` name แล้วใส่ตัวโคลนลงใน `MyEnum::B` ได้ แต่นั่นจะเป็นตัวอย่างของแอนติแพตเทิร์น
[โคลนเพื่อเอาใจ borrow checker](../anti_patterns/borrow_clone.md)
อย่างไรก็ตาม เราหลีกเลี่ยงการจัดสรรหน่วยความจำเพิ่มเติมได้โดยเปลี่ยน `e` ผ่านการยืมแบบแก้ไขได้เท่านั้น

`mem::take` ช่วยให้เราเอาค่าออกมา โดยแทนที่ด้วยค่า default ของมัน แล้วคืนค่าเดิมกลับมา สำหรับ `String` ค่า default คือ `String` ว่าง ซึ่งไม่ต้องจัดสรรหน่วยความจำ ผลลัพธ์คือเราได้ `name` ตัวเดิม*ในฐานะค่าที่เป็นเจ้าของ* เราจึงนำมันไปห่อใน enum อีกตัวได้

**หมายเหตุ:** `mem::replace` คล้ายกันมาก แต่เปิดให้เราระบุได้ว่าจะแทนที่ค่าด้วยอะไร บรรทัดที่เทียบเท่ากับ `mem::take` ของเราคือ
`mem::replace(name, String::new())`

อย่างไรก็ตาม พึงสังเกตว่าหากเราใช้ `Option` และต้องการแทนที่ค่าของมันด้วย `None` เมท็อด `take()` ของ `Option` ก็เป็นทางเลือกที่สั้นกว่าและเป็นสำนวนมากกว่า

## ข้อดี

ดูสิแม่ ไม่มีการจัดสรรหน่วยความจำเลย! แถมคุณอาจรู้สึกเหมือนอินเดียนา โจนส์ตอนทำด้วย

## ข้อเสีย

โค้ดยาวขึ้นเล็กน้อย การทำผิดซ้ำแล้วซ้ำเล่าจะทำให้คุณเกลียด borrow checker คอมไพเลอร์อาจล้มเหลวในการ optimize การเขียนค่าทับซ้อน (double store) ออกไป ส่งผลให้ประสิทธิภาพลดลงเมื่อเทียบกับสิ่งที่คุณจะทำในภาษา unsafe

ยิ่งไปกว่านั้น ชนิดข้อมูลที่คุณดึงค่าออกมาจะต้องอิมพลีเมนต์
[trait `Default`](./default.md) แต่ถ้าชนิดข้อมูลที่คุณใช้อยู่ไม่อิมพลีเมนต์ trait นี้ คุณก็ใช้ `mem::replace` แทนได้

## การอภิปราย

แพตเทิร์นนี้เป็นเรื่องน่าสนใจเฉพาะใน Rust ในภาษาแบบ GC คุณจะอ้างอิงถึงค่าโดยปริยาย (และ GC จะติดตาม ref ให้) ส่วนในภาษาระดับต่ำอื่นๆ อย่าง C คุณก็แค่ตั้ง alias พอยน์เตอร์แล้วค่อยไปแก้ทีหลัง

อย่างไรก็ตาม ใน Rust เราต้องทำงานเพิ่มขึ้นเล็กน้อยเพื่อทำสิ่งนี้ ค่าที่เป็นเจ้าของมีเจ้าของได้เพียงหนึ่งเดียว ดังนั้นการดึงมันออกมาจึงต้องใส่บางสิ่งกลับเข้าไป – เหมือนอินเดียนา โจนส์ ที่เอาถุงทรายสลับกับโบราณวัตถุ
