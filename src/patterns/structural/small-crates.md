# เลือกใช้ครีตขนาดเล็ก

## คำอธิบาย

เลือกใช้ครีตขนาดเล็กที่ทำสิ่งหนึ่งได้ดี

Cargo และ crates.io ทำให้การเพิ่มไลบรารีของบุคคลที่สามเป็นเรื่องง่าย มากกว่าในภาษา C หรือ C++ เสียอีก ยิ่งไปกว่านั้น เนื่องจากแพ็กเกจบน crates.io ไม่สามารถแก้ไขหรือลบได้หลังจากเผยแพร่แล้ว การบิลด์ใดที่ทำงานได้ตอนนี้ก็ควรทำงานได้ต่อไปในอนาคต เราควรใช้ประโยชน์จากเครื่องมือนี้ และใช้ดีเพนเดนซีที่มีขนาดเล็กและแยกส่วนย่อยมากกว่า

## ข้อดี

- ครีตขนาดเล็กเข้าใจง่ายกว่า และส่งเสริมโค้ดที่เป็นโมดูลมากขึ้น
- ครีตช่วยให้ใช้โค้ดซ้ำระหว่างโปรเจกต์ได้ ตัวอย่างเช่น ครีต `url` ถูกพัฒนาเป็น
  ส่วนหนึ่งของเบราว์เซอร์เอนจิน Servo แต่ต่อมาก็ถูกนำไปใช้อย่างแพร่หลายนอก
  โปรเจกต์นั้น
- เนื่องจากหน่วยการคอมไพล์ของ Rust คือครีต การแยกโปรเจกต์ออกเป็นหลายครีตจึง
  ช่วยให้คอมไพล์โค้ดได้พร้อมกันมากขึ้น

## ข้อเสีย

- อาจนำไปสู่ "นรกดีเพนเดนซี" (dependency hell) เมื่อโปรเจกต์พึ่งพาครีตหลาย
  เวอร์ชันที่ขัดแย้งกันพร้อมกัน ตัวอย่างเช่น ครีต `url` มีทั้งเวอร์ชัน 1.0 และ 0.5
  เนื่องจาก `Url` จาก `url:1.0` กับ `Url` จาก `url:0.5` เป็นคนละชนิดกัน
  ไคลเอนต์ HTTP ที่ใช้ `url:0.5` จึงไม่รับค่า `Url` จากตัวดึงข้อมูลเว็บที่ใช้
  `url:1.0`
- แพ็กเกจบน crates.io ไม่ได้ผ่านการคัดสรร ครีตอาจเขียนมาไม่ดี มีเอกสาร
  ประกอบที่ไร้ประโยชน์ หรือเป็นอันตรายโดยสิ้นเชิง
- ครีตขนาดเล็กสองครีตอาจ optimize ได้น้อยกว่าครีตใหญ่หนึ่งครีต เนื่องจาก
  คอมไพเลอร์ไม่ได้ทำ link-time optimization (LTO) โดยค่าเริ่มต้น

## ตัวอย่าง

ครีต [`url`](https://crates.io/crates/url) มีเครื่องมือสำหรับทำงานกับ URL

ครีต [`num_cpus`](https://crates.io/crates/num_cpus) มีฟังก์ชันสำหรับสอบถามจำนวน CPU บนเครื่อง

ครีต [`ref_slice`](https://crates.io/crates/ref_slice) มีฟังก์ชันสำหรับแปลง `&T` เป็น `&[T]` (ตัวอย่างเชิงประวัติศาสตร์)
