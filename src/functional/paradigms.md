# กระบวนทัศน์การเขียนโปรแกรม

หนึ่งในอุปสรรคที่ใหญ่ที่สุดในการทำความเข้าใจโปรแกรมเชิงฟังก์ชันสำหรับผู้ที่มาจากพื้นฐานเชิงอิมเพอเรทีฟคือการเปลี่ยนวิธีคิด โปรแกรมเชิงอิมเพอเรทีฟอธิบาย**อย่างไร**ที่จะทำสิ่งหนึ่ง ขณะที่โปรแกรมแบบประกาศ (declarative) อธิบาย**อะไร**ที่ต้องทำ ลองบวกเลขตั้งแต่ 1 ถึง 10 เพื่อสาธิตเรื่องนี้

## เชิงอิมเพอเรทีฟ

```rust
let mut sum = 0;
for i in 1..11 {
    sum += i;
}
println!("{sum}");
```

กับโปรแกรมเชิงอิมเพอเรทีฟ เราต้องเล่นเป็นคอมไพเลอร์เองเพื่อดูว่าเกิดอะไรขึ้น ในที่นี้ เราเริ่มต้นด้วย `sum` เท่ากับ `0` ต่อมาเราวนซ้ำผ่านช่วงตั้งแต่ 1 ถึง 10 ทุกรอบของลูป เราบวกค่าที่สอดคล้องกันในช่วงนั้นเข้าไป แล้วจึงพิมพ์มันออกมา

| `i` | `sum` |
| :-: | :---: |
|  1  |   1   |
|  2  |   3   |
|  3  |   6   |
|  4  |  10   |
|  5  |  15   |
|  6  |  21   |
|  7  |  28   |
|  8  |  36   |
|  9  |  45   |
| 10  |  55   |

นี่คือวิธีที่พวกเราส่วนใหญ่เริ่มเขียนโปรแกรม เราเรียนรู้ว่าโปรแกรมคือชุดของขั้นตอน

## แบบประกาศ (Declarative)

```rust
println!("{}", (1..11).fold(0, |a, b| a + b));
```

โอ้โฮ! นี่ต่างออกไปจริงๆ! เกิดอะไรขึ้นตรงนี้? จำไว้ว่ากับโปรแกรมแบบประกาศ เรากำลังอธิบาย**อะไร**ที่ต้องทำ ไม่ใช่**อย่างไร**ที่ต้องทำ `fold` เป็นฟังก์ชันที่
[ประกอบ](https://en.wikipedia.org/wiki/Function_composition)ฟังก์ชันเข้าด้วยกัน ชื่อนี้เป็นธรรมเนียมจาก Haskell

ในที่นี้ เรากำลังประกอบฟังก์ชันการบวก (โคลเชอร์นี้: `|a, b| a + b`) เข้ากับช่วงตั้งแต่ 1 ถึง 10 โดย `0` คือจุดเริ่มต้น ดังนั้น `a` จึงเป็น `0` ในตอนแรก `b` คือสมาชิกตัวแรกของช่วง นั่นคือ `1` ผลลัพธ์คือ `0 + 1 = 1` ตอนนี้เรา `fold` อีกครั้ง โดย `a = 1`, `b = 2` ผลลัพธ์ถัดไปจึงเป็น `1 + 2 = 3` กระบวนการนี้ดำเนินต่อไปจนเราถึงสมาชิกตัวสุดท้ายในช่วง นั่นคือ `10`

| `a` | `b` | ผลลัพธ์ |
| :-: | :-: | :----: |
|  0  |  1  |   1    |
|  1  |  2  |   3    |
|  3  |  3  |   6    |
|  6  |  4  |   10   |
| 10  |  5  |   15   |
| 15  |  6  |   21   |
| 21  |  7  |   28   |
| 28  |  8  |   36   |
| 36  |  9  |   45   |
| 45  | 10  |   55   |
