# โคลนเพื่อเอาใจ borrow checker

## คำอธิบาย

borrow checker ป้องกันไม่ให้ผู้ใช้ Rust เขียนโค้ดที่ไม่ปลอดภัย โดยรับประกันว่าต้องเป็นอย่างใดอย่างหนึ่ง: มีเรฟเฟอเรนซ์ที่แก้ไขได้เพียงหนึ่งเดียว หรือมีเรฟเฟอเรนซ์ได้หลายตัวแต่ทั้งหมดแก้ไขไม่ได้ หากโค้ดที่เขียนไม่เป็นไปตามเงื่อนไขเหล่านี้ แอนติแพตเทิร์นนี้จะเกิดขึ้นเมื่อนักพัฒนาแก้ข้อผิดพลาดของคอมไพเลอร์ด้วยการโคลนตัวแปร

## ตัวอย่าง

```rust
// define any variable
let mut x = 5;

// Borrow `x` -- but clone it first
let y = &mut (x.clone());

// without the x.clone() two lines prior, this line would fail on compile as
// x has been borrowed
// thanks to x.clone(), x was never borrowed, and this line will run.
println!("{x}");

// perform some action on the borrow to prevent rust from optimizing this
//out of existence
*y += 1;
```

## แรงจูงใจ

เป็นเรื่องน่าดึงดูดใจ โดยเฉพาะสำหรับผู้เริ่มต้น ที่จะใช้แพตเทิร์นนี้แก้ปัญหาชวนสับสนกับ borrow checker อย่างไรก็ตาม มันมีผลลัพธ์ร้ายแรงตามมา การใช้ `.clone()` ทำให้เกิดสำเนาข้อมูลขึ้นมา การเปลี่ยนแปลงใดๆ ระหว่างทั้งสองจะไม่ถูกซิงค์กัน ราวกับว่ามีตัวแปรสองตัวที่แยกจากกันโดยสิ้นเชิง

มีกรณีพิเศษ - `Rc<T>` ถูกออกแบบมาให้จัดการการโคลนอย่างชาญฉลาด มันจัดการสำเนาข้อมูลเพียงชุดเดียวไว้ภายใน การเรียก `.clone()` บน `Rc` สร้างอินสแตนซ์ `Rc` ใหม่ซึ่งชี้ไปยังข้อมูลชุดเดียวกับ `Rc` ต้นทาง พร้อมเพิ่มจำนวนเรฟเฟอเรนซ์ขึ้นหนึ่ง เช่นเดียวกับ `Arc` ซึ่งเป็นคู่หูที่ปลอดภัยต่อเธรดของ `Rc`

โดยทั่วไป การโคลนควรทำอย่างตั้งใจและเข้าใจผลลัพธ์อย่างถ่องแท้ หากการโคลนถูกใช้เพื่อทำให้ข้อผิดพลาดของ borrow checker หายไป นั่นเป็นสัญญาณที่ดีว่าแอนติแพตเทิร์นนี้อาจถูกใช้อยู่

แม้ว่า `.clone()` เป็นสัญญาณของแพตเทิร์นที่ไม่ดี แต่บางครั้ง**การเขียนโค้ดที่ไม่มีประสิทธิภาพก็เป็นเรื่องที่ยอมรับได้** ในกรณีเช่น:

- นักพัฒนายังใหม่กับความเป็นเจ้าของ
- โค้ดไม่มีข้อจำกัดเรื่องความเร็วหรือหน่วยความจำที่เข้มงวด (เช่น โปรเจกต์
  hackathon หรือต้นแบบ)
- การทำให้ borrow checker พอใจซับซ้อนมาก และคุณเลือกเพิ่มความอ่านง่ายแทน
  ประสิทธิภาพ

หากสงสัยว่ามีการโคลนที่ไม่จำเป็น ควรทำความเข้าใจ
[บทว่าด้วย Ownership ในหนังสือ The Rust Book](https://doc.rust-lang.org/book/ownership.html)
อย่างถ่องแท้ก่อนตัดสินว่าการโคลนนั้นจำเป็นหรือไม่

นอกจากนี้ อย่าลืมรัน `cargo clippy` ในโปรเจกต์ของคุณเสมอ ซึ่งจะตรวจจับบางกรณีที่ `.clone()` ไม่จำเป็นได้
